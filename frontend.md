# MedAtlas local frontend

The local Next.js app at `http://127.0.0.1:3002` uses the supplied MedAtlas visual design. The landing page has a translucent anatomical brain and light sparks. The dashboard has a quiet anatomical heart and heartbeat animation, a light grain texture, scroll reveal, and three larger pastel cards. The document panel has one offline upload control that starts the complete medical ingestion pipeline.

The login dialog has two options: `Log in` and `Create your account`. Both use name, date of birth, and an eight-character password. The backend creates a unique `usr_...` ID, stores an scrypt password hash, and issues a local HttpOnly session cookie. `/workspace` and every medical API endpoint require that session. Each document is linked to the signed-in user and is filtered from other accounts. The Health Trends panel includes a local question bar that calls the guarded, evidence-grounded `/api/chat` pipeline and shows citations or an abstention. The Insurance Claim panel asks for a policy reference ID, shows the claim-document checklist and missing-document reminder, then copies tagged `Insurance & Consent` files into a user-selected local `Insurance documents` folder.

The frontend proxies `/api/*` to the local FastAPI server on `127.0.0.1:8765`, so browser cookies stay on one origin. Run `./start-local.ps1` from PowerShell to start both services. The app uses only localhost model and storage services; it does not need internet access. See [backend.md](backend.md) for local startup and offline requirements. The current hosted Site is a separate deployment and cannot connect to this offline backend.
